# Поиск услуг: отбор кандидатов

Решение возвращает до 50 уникальных объявлений для поискового запроса.
В `solution.ipynb` сравниваются BM25, веса полей, word/character TF-IDF,
две dense-модели и их объединение через RRF. Финальная выдача учитывает
локацию поиска и известные позитивные пары из `train`. Модели не дообучаются.

## Результат

В основе — **BM25 + multilingual-e5-small → RRF**: по 200 кандидатов от каждого
канала, `c=60`, равные веса. Для локации запроса отдельно извлекаются кандидаты
из объявлений той же локации. Первые 40 мест заполняются локальным RRF,
оставшиеся — глобальной выдачей. Если локальных объявлений нет, используется
глобальная выдача. Затем в начало добавляются доступные в корпусе позитивы
из `train` с тем же нормализованным текстом и категорией: сначала из той же
локации, затем остальные. После удаления дублей остаётся не более 50 `item_id`.

Для финального `answer.csv` на платформе получен **Recall@50 = 0,736026**.
Это результат итоговых запросов; локальные значения ниже относятся к другому
набору запросов и напрямую с ним не сравниваются.

| Метод | Macro Recall@50 |
| --- | ---: |
| BM25 | 1,9168% |
| Word TF-IDF | 1,5504% |
| Character TF-IDF | 1,3516% |
| Dense | 1,8395% |
| BM25 + dense, RRF | 2,1566% |

Прирост глобального RRF к BM25 — **+0,2399 п.п.**; скорректированный
bootstrap-интервал 98,33%: **[+0,1580; +0,3237] п.п.** Эти варианты сохранены
в `experiments.csv`. Географический отбор проверяется отдельно в ноутбуке.

В validation отложены 20% уникальных нормализованных текстов, seed 42;
контексты одного текста остаются вместе. Позитивы вне корпуса учитываются
в знаменателе, поэтому потолок Recall@50 — около 6,13%. По доступным позитивам
Recall@50 глобального RRF составляет 33,60%. Конфигурация глобального RRF выбрана
на этом же validation. При оценке географического отбора разметка validation
используется только для подсчёта метрики. Позитивы из `train` добавляются лишь
при создании итогового `answer.csv`.

## Файлы

- `solution.ipynb` — исследование, проверка географического отбора и генерация ответа.
- `answer.csv` — итоговая выдача для 2 452 запросов.
- `split.csv`, `experiments.csv` — фиксированный split и результаты экспериментов.
- `requirements.txt` — версии зависимостей.

В `dataset/` нужны `benchmark_items.parquet` (189 212 объявлений),
`benchmark_queries.parquet` (2 452 запроса) и `train.parquet` (497 673 взаимодействия).
Каждое взаимодействие считается позитивом; исходные файлы не изменяются.

## Запуск

Python 3.12, команды из корня проекта:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m ipykernel install --user --name avito --display-name avito
```

Для полного запуска ноутбука один раз загрузите веса обеих dense-моделей:

```bash
python - <<'PY'
from huggingface_hub import snapshot_download
snapshot_download(
    "intfloat/multilingual-e5-small",
    revision="614241f622f53c4eeff9890bdc4f31cfecc418b3",
    cache_dir=".cache/huggingface",
    allow_patterns=["*.json", "*.safetensors", "tokenizer*", "sentencepiece*", "*.txt"],
    ignore_patterns=["onnx/*", "openvino/*"],
)
snapshot_download(
    "microsoft/harrier-oss-v1-270m",
    revision="31de22b673913c7d658c0f03f792d77c2dcf8ebd",
    cache_dir=".cache/huggingface",
)
PY
```

Откройте `solution.ipynb`, выберите kernel `avito` и выполните все ячейки.
Индексы и embeddings пересоздаются; `answer.csv` обновляется автоматически.
После установки зависимостей и загрузки весов интернет не требуется.
Для повторного запуска с проверенным кешем Harrier установите
`AVITO_REUSE_H270=1`; без него embeddings Harrier пересчитываются.

`AVITO_DEVICE=auto` выбирает CUDA → MPS → CPU; доступны явные `cpu`, `cuda`, `mps`.
Переменную задавайте до запуска kernel. BM25 и TF-IDF всегда работают на CPU.
Сборку PyTorch выбирайте по [официальной инструкции](https://pytorch.org/get-started/locally/).
Основные эксперименты проверены на RTX 5090; CPU — отдельными проверками,
реальный MPS не проверен. Финальные ячейки с географией после изменения
проверены по синтаксису, полный повторный прогон ноутбука не завершён.
Character TF-IDF требует нескольких ГиБ RAM; embeddings корпуса занимают 277 МиБ.
